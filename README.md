# Superset Analytics Map

Эта папка предназначена для документации по аналитике в Superset: откуда приходят данные, как они попадают в ADB, как из них собираются датасеты и как чарты дополнительно агрегируют данные.

Главная идея: документируем не только визуализации, а весь путь данных.

```text
Внешний источник / внутренняя БД / API
  -> загрузка или ETL-процесс
  -> таблицы / представления в ADB
  -> Superset dataset
  -> Superset chart
  -> Superset dashboard
```

## Структура

```text
superset_analytics_map/
  README.md
  glossary.md
  lineage-map.md
  sources/
  ingestion/
  datasets/
  charts/
  dashboards/
  templates/
```

## Как заполнять

1. Сначала описываем источники данных в `sources/`.
2. Затем описываем процессы загрузки и обновления в `ingestion/`.
3. После этого описываем датасеты Superset в `datasets/`.
4. Для каждого чарта создаем файл в `charts/` и указываем датасет, метрики, группировки и фильтры.
5. Для каждого дашборда создаем файл в `dashboards/` и перечисляем связанные чарты.
6. Общую карту зависимостей поддерживаем в `lineage-map.md`.

## Основные правила

- Один датасет Superset = один `.md` файл в `datasets/`.
- Один чарт Superset = один `.md` файл в `charts/`.
- Один дашборд Superset = один `.md` файл в `dashboards/`.
- SQL virtual dataset нужно сохранять полностью.
- Для каждого датасета нужно явно указывать grain: что означает одна строка.
- Для каждого чарта нужно явно указывать, агрегирует ли он данные дополнительно.
- Если данные обновляются через cron, n8n или другой процесс, этот процесс должен быть описан отдельно в `ingestion/`.

## Для AI-агента

В начале файлов используем YAML front matter. Это делает документацию более машинно-читаемой и помогает AI-агенту быстро строить граф зависимостей.

Пример:

```yaml
---
type: dataset
name: marketplace_daily_stats
superset_type: virtual
database: ADB
depends_on:
  - raw_ozon_orders
  - raw_wb_orders
used_by_charts:
  - revenue_by_day
---
```
